📌 Objetivo
Desarrolla un nodo LangGraph llamado identificacion_manual basado en LLM, que siga la estructura del proyecto y utilice el estado definido en models/eroski_state.py.

🎯 Funcionalidad del nodo
Este nodo conversa con el usuario para recopilar los siguientes campos:

nombre

apellido

nombre de la tienda donde ocurre la incidencia

nombre de la sección

número de empleado

Y los guarda en los siguientes canales del estado:

employee_id ← número de empleado

employee_name ← nombre + apellido

incident_store_name ← nombre de la tienda

incident_department ← nombre de la sección

store_id ← código de la tienda (extraído de maestro_tiendas)

✅ Requisitos funcionales del nodo
El usuario puede introducir uno, varios o todos los datos.

El nodo conserva los datos recogidos en el estado.

El nodo muestra al usuario, en cada turno, los datos que ya ha recogido.

El usuario puede corregir cualquier dato en cualquier momento (por ejemplo: "quiero cambiar el número de empleado").

El nodo no avanza hasta que todos los campos estén completos y confirmados.

🏬 Lógica específica para la tienda
El usuario introduce el nombre de la tienda con lenguaje natural.

El LLM compara esa entrada con los nombres de la tabla maestro_tiendas de la base de datos PostgreSQL, que tiene:

codigo_tienda

nombre_tienda

El LLM selecciona el nombre más probable.

Se muestra al usuario el nombre y código sugerido, y se solicita confirmación con la herramienta nodes/tools/confirmation_tool.py.

Si el usuario confirma, se guardan:

incident_store_name

store_id

La tabla se recupera una vez y se mantiene en memoria para evitar múltiples consultas. La conexión a la base de datos se configura desde el archivo .env.

🧠 Comportamiento adicional sugerido
Validación y normalización: transforma entradas mal escritas en datos limpios. Ejemplo: "erosky bilbando" → "Hipermercado Bilbondo"

Orden lógico sugerido: nombre → número empleado → tienda → sección, pero permite entrada flexible.

Resumen parcial en cada turno, por ejemplo:

Resistencia a ambigüedades: si el LLM no tiene seguridad, debe usar la tool de confirmación.

Mensajes claros y empáticos.

⚙️ Consideraciones técnicas
Usar asyncpg o psycopg2 para conectar con PostgreSQL.

Usar Command(update={...}) como retorno del nodo.

Usar ChatOpenAI o modelo configurado por get_llm().

Añadir logging útil (self.logger.info(...)) para cada paso.

Separar funciones como:
